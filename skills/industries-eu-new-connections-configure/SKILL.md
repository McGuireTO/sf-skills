# Querying Eu New Connections Setup

## When to Use This Skill

Sets up "New Connection Setup" (Individual Application milestone + SLA tracking) in an Energy & Utilities Cloud org that has the E&U license provisioned but nothing else configured. Use when a user says "set up new connection setup for Energy & Utilities", "enable individual application milestone tracking", or "stand up SLA milestone tracking for E&U". This is an ENTRY-POINT SOR: execute phases in declared `phases[]` order, honoring `depends_on` edges. Execute phase-by-phase directly from this recipe: at each phase boundary, RE-READ this SOR's `steps` + `agent_guidance` for the next phase before acting — do not execute from an up-front summarized plan. The per-step guidance carries org-proven gotchas (the Phase 2 profile-fork gate and per-org permission-dependency iteration, the exact Phase 6a FlexiPage Tooling envelope) that a summary silently drops. The headless phases (pref enablement, profile clone, user creation, permission-set assignment, record-page creation) run end-to-end; Phase 7 (the two business flows) is a pure needs-human handoff the agent must surface rather than fake — the flows are managed-package artifacts whose source is not retrievable on a subscriber org. Phase 1 flips both org prefs (euIndvAppEntlFeature then euSimplifiedSlaSetup) via the SAME E&U settings controller (setIndustriesEnergyUtilitiesPref); Phase 2 clones the "New Connection Manager" profile by delegating to the managing-profiles SOR (metadata_api clone via /headless/metadata + a Profile metadata PUT for the role permissions; data-API clone kept as a fallback where Profile.createable is true); Phase 3 OPTIONALLY creates a dedicated connection- manager User via the data API (skip it to let the admin manage connections themselves); Phase 5 assigns the packaged "EAndU Cloud Program Access" permission set via the data API to each recipient — always the running admin, plus the dedicated user if Phase 3 ran, plus any other user the admin names — that permset already carries the Individual Application SLA-field FLS, so there is NO separate FLS phase; Phase 7 is a pure handoff — the two business flows are managed-package artifacts the admin clones/customizes/activates in Flow Builder (not programmatically installable on a subscriber org). PARTIALLY ORG-VALIDATED on an internal test org (Phases 3, 5 mutations confirmed; Phase 1a euIndvAppEntlFeature confirmed; Phase 1b euSimplifiedSlaSetup confirmed 2026-08-09 — write→read-back SUCCESS; the EAndU Cloud Program Access permset's 7-field FLS confirmed 2026-08-07). Phase 1b's FORMER 403 blocker is RESOLVED: the E&U team landed euSimplifiedSlaSetup, a first-class admin-grantable pref that flips the platform Simplified SLA Setup preference without touching the org-provisioned Entitlements gate. It replaces the earlier SLA-management permission path that 403'd. When all phases complete, surface the closing message in Phase 7's agent_guidance verbatim — it lists the two business-specific flows the admin may want to clone, activate, and customize (each backed by a Decision Matrix the admin defines themselves).

## Critical Constraints

**Preconditions:**

- The org must have the Energy & Utilities Cloud license provisioned. The E&U settings controller gates every pref write on "Energy and Utilities settings access"; without the license the euIndvAppEntlFeature toggle is not writable (and getIndustriesEnergyUtilitiesPrefs will not expose it as an enable-able pref). No API provisions a license.
 (check: `IndustriesEnergyAndUtilities.orgHasEnergyUtilities`)
- The Individual Application Entitlement feature (euIndvAppEntlFeature) must be ON before Phase 1b (euSimplifiedSlaSetup) can be enabled. Simplified SLA Setup's access gate requires the Individual Application Entitlement feature, which is satisfied only once euIndvAppEntlFeature is turned on. Phase 1a satisfies this; the depends_on edge on enable-simplified-sla enforces order. NOTE: this SUPERSEDES the former entitlement-management and ITSM-setup-access preconditions, which gated the retired SLA-management permission path (org-provisioned Entitlements / ITSM-setup-access gates). The E&U pref path does not touch either gate — org-validated on an internal test org 2026-08-09 with no 403.
 (check: `IndustriesEnergyAndUtilities.orgHasIASlaFeatureEnabled`)
